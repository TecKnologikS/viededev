Bruno : remplacer Postman par un dossier dans ton dépôt

660609b25 nov. 20265 min de lecture#api #outils #git #open-source

Bruno est un client API open source, sous licence MIT. Tes requêtes ne partent pas dans un cloud : elles vivent dans un dossier de fichiers texte, que tu ranges dans ton dépôt à côté du code.

D’où vient ce guide. Il suit la documentation officielle et le README de Bruno, lus le 25/11/2026 (version 4.4.0, 48,6 k étoiles sur GitHub). Les noms de menus sont ceux de la doc, en anglais.

Ce que ça change par rapport à Postman

  • Une collection est un dossier. Un fichier par requête, lisible dans n’importe quel éditeur.
  • Elle se versionne avec Git. Une requête modifiée apparaît dans le diff de la pull request, comme le reste du code.
  • Pas de synchro cloud. Le README est clair : Bruno fonctionne hors ligne, et aucune synchro cloud n’est prévue, « jamais ».

L’installer

Le binaire se télécharge sur usebruno.com/downloads pour Mac, Windows et Linux. Ou avec un gestionnaire de paquets :

brew install bruno              # macOS
winget install Bruno.Bruno      # Windows
choco install bruno             # Windows
snap install bruno              # Linux
flatpak install com.usebruno.Bruno

Importer une collection Postman

Dans Postman :

  1. Clique sur la collection, puis Export.
  2. Choisis Collection v2 ou Collection v2.1, puis Export.
  3. Enregistre le fichier .json.

Dans Bruno :

  1. Clique sur + en haut à gauche, puis Import Collection.
  2. Glisse le fichier .json, ou clique pour le choisir.
  3. Clique Import.

Pour un environnement : dans Postman, menu … à côté de l’environnement, puis Export. Dans Bruno, icône Environments en haut à droite, Configure environments, puis Import environment.

Trois choses à savoir :

  • Les scripts sont traduits. À l’import, Bruno convertit les appels courants (pm.test, pm.environment, pm.globals, pm.collectionVariables, pm.response). Pour les garder tels quels, il y a l’option Preserve scripts, dans Options > Show Advanced Options.
  • Les paquets npm de Postman ne passent pas. Un script qui utilise postman-collection, newman ou @postman/* est à réécrire.
  • L’import en masse est payant. Importer d’un coup l’export complet de Postman (toutes les collections et tous les environnements) est réservé à l’édition Ultimate. Collection par collection, c’est gratuit.

À quoi ressemble le dossier

Depuis Bruno 3.0.0, les requêtes s’écrivent en YAML. C’est le format que la doc recommande pour les nouvelles collections. L’ancien format .bru reste pris en charge.

ma-collection/
├── opencollection.yml
├── environments/
│   └── development.yml
├── users/
│   ├── folder.yml
│   ├── create-user.yml
│   ├── get-user.yml
│   └── delete-user.yml
└── orders/
    └── create-order.yml

Le début d’un fichier de requête, tiré de l’exemple de la doc :

info:
  name: Create User
  type: http
  seq: 1

http:
  method: POST
  url: https://api.example.com/users
  body:
    type: json

L’exemple complet ajoute le contenu du corps et un script de tests qui vérifie le statut 201.

Une collection au format .bru a la même forme, avec bruno.json à la racine et un fichier .bru par requête.

La versionner avec Git

La collection est un dossier : place-la dans ton dépôt et pousse-la comme le reste.

git add api/
git commit -m "requêtes API"
git push

Le piège. Bruno a aussi une interface Git intégrée, et elle n’est pas entièrement gratuite :

Dans l’interface de Bruno Édition
init, voir les diffs, vérifier les mises à jour, pull, clone gratuite
commit, push, branches, résolution des conflits Pro ou Ultimate

Tu n’en as pas besoin. La doc présente deux façons de collaborer : l’interface de Bruno, ou les commandes Git dans le terminal. La seconde ne coûte rien.

Les secrets

Une collection versionnée ne doit contenir aucun secret. Bruno propose deux moyens.

Les variables secrètes. Coche une variable d’environnement comme secrète : sa valeur est stockée sur ta machine, chiffrée, et le fichier d’environnement ne garde que son nom. Elle n’est pas exportée avec la collection et s’affiche **** dans les rapports.

Un fichier .env, à la racine du dossier de collection :

JWT_TOKEN=your_jwt_token_value
API_KEY=your_api_key_value

Dans une requête ou un environnement, tu l’appelles avec {{process.env.JWT_TOKEN}}.

  • Ajoute .env à ton .gitignore. La doc insiste.
  • Versionne à la place un .env.sample sans les vraies valeurs, pour que tes collègues sachent quoi remplir.
  • Une valeur qui contient un # se met entre guillemets doubles.

Lancer les requêtes sans l’interface

La ligne de commande s’installe avec npm (Node 18 ou plus récent) :

npm install -g @usebruno/cli

Depuis le dossier de la collection (celui qui contient opencollection.yml ou bruno.json) :

bru run                       # toute la collection
bru run users --env Local     # un dossier, avec un environnement
bru run -r                    # en parcourant les sous-dossiers

Les options utiles :

Option Rôle
--env choisit l’environnement
--env-var apiKey=valeur passe une variable, par exemple un secret
--bail s’arrête au premier échec
--reporter-junit results.xml écrit un rapport JUnit (aussi --reporter-json, --reporter-html)

En CI

Bruno fournit une action GitHub. L’exemple minimal de la doc, à placer dans .github/workflows/ :

name: API Tests
on: [pull_request, push]

jobs:
  bruno:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: usebruno/bruno-cli-action@v1
        with:
          working-directory: tests/payments
          command: 'run --env prod'

Ailleurs que sur GitHub, il y a l’image Docker usebruno/cli, ou la commande directe :

bru run --env ci --reporter-junit results.xml

Tout ce que décrit ce guide tient dans l’édition gratuite : le client, l’import d’une collection, les fichiers dans ton dépôt, la ligne de commande, la CI. Ce que tu paies, c’est du confort : les boutons commit et push dans l’interface, l’import en masse depuis Postman.
